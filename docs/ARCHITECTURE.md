# Code layout

Where things live. Numbers (stops, characters, relics, card counts) are in [`GAME_FACTS.md`](GAME_FACTS.md), not repeated here.

- `combat/` - rules only: no nodes, no scenes. `Combat` drives turns and emits signals; `CardPiles`, `Combatant`, `EnemyUnit`, `CardData`, `CardEffect`, `EnemyData` are the building blocks. `starter_content.gd` holds placeholder cards and enemies.
- `battle.gd` / `battle.tscn` - the combat UI. It observes `Combat` signals and calls `play_card` / the discard-step API (`begin_discard`, `toggle_discard`, `confirm_discard`, `cancel_discard`; see "Hand and discard rules"); it contains no rules. Run on its own (F6 on `battle.tscn`) it plays a random fight with a New Fight button; embedded by the run screen it shows a fight the run built and ends with Continue.
  `Battle` is a coordinator (about 650 lines) that composes small helpers under `run/battle/`: `BattleHand` (the hand's views: rebuild, fit, hover, preview, play), `BattleDrag`, `BattleHud` (turn controls, the four pile buttons, journey info), `BattleOverlays` (choice and pile viewer), `BattleFx` (phase banner, flash, boss intro, pile cues), `BattleKeys` (keyboard input), `BattleDamagePreview` and `BattleTooltips` (the status and enemy tooltip text). Tests reach the helpers through members such as `_hand`, `_hud`, `_fx` and `_overlays`.
- `run/card_view.gd` draws a card (layout, interaction and state); its icon drawing is in `run/card_icons.gd` (`CardIcons`, static), the frame colours in `run/card_palette.gd` (`CardPalette`) and the hover tooltip in `run/card_tooltip.gd` (`CardTooltip`). A number changed by a status shows a green or red tint and a small up or down triangle.
- `run/painted_art.gd` loads and caches the painted art on the main thread only (decoding the same texture from a worker thread crashed intermittently, so it is not threaded). The next stop's art is queued and decoded a few milliseconds per frame by `run.gd` (`queue_for_stop`, `pump`); a screen that needs a texture still decodes it at once.
- `docs/RESKIN.md` - the v0.5.0 "The Unforgotten" presentation reskin: renamed enemies, new story and menu style, same rules and IDs (name map inside).
- `docs/reference/` - screen reference sheets (web pages with an in-game capture, the art and the code for every screen). **No longer in the repository** (removed in the November 2026 history rewrite, see `docs/REPO_SIZE.md`); the folder is git-ignored, so a local copy can sit there without being tracked. A `.gdignore` keeps Godot from importing their images.
- `run/run_state.gd` - the run layer, rules only: a stop sequence: the route map that New Journey plays since v0.9.0 (`run/route_map.gd`, `docs/MAP_DESIGN.md`), or the fixed line of stops it replaced (`new_runs_use_map` in `run.gd`; story beats, regular fights, rests, vendors, the Brakeman as a mid-boss halfway and a Conductor boss fight at the end; the counts are in `docs/GAME_FACTS.md`, the design in `docs/LEVELS_DESIGN.md`) with the player's HP and deck carried from stop to stop. Wins pay gold and offer a pick-one-of-three card reward (the Conductor pays no gold and offers none; the Brakeman (shown in game as Bellkeeper) carries at most 9 Haunt stacks, `max_haunt` on `EnemyData`, so the Medium cannot Haunt it to death before it acts; the mid-boss pays gold plus a bonus and offers a card, and the run goes on; both bosses have a second phase at 50% HP, `phase_two_intents` on `EnemyData`, see `docs/ADDING_CONTENT.md`); a rest stop offers two choices, Rest (heal to full) or Remember (bring one card back stronger, no heal; see Remembered below), with a short story card, `run/rest_content.gd`, continues the voice from the opening beat); a defeat ends the run; passing the last stop escapes. Each run is played as a character (`run/character.gd`, `data/characters/`): the Deserter, the Thief, the Medium or the Stray (HP and card counts in `docs/GAME_FACTS.md`), each with its own starting deck and a card pool of the neutral cards plus its own (a card's `character` tag; empty means neutral). Combat on its own, and the combat sim, use 40 HP. Class design: `docs/CLASSES_PLAN.md`. `run/vendor.gd` is the vendor visit (3 cards for sale, one relic, remove a card, heal; placeholder prices), `run/story_beat.gd` / `run/story_content.gd` + `data/story/` are the cutscene beats (the four beats of the line, with per-character versions of three). Relics (`combat/relic_data.gd`, `data/relics/`, `docs/RELICS_DESIGN.md`) are passive items (the count is in `docs/GAME_FACTS.md`), bought one per vendor visit. New stop kinds are new `StopType` values plus one branch in `run.gd`.
- `run.gd` / `run.tscn` - the run screen (main scene, F5): a thin coordinator over `RunState` that embeds `battle.tscn` for combat stops; each other screen (character select, story, reward, vendor, rest, end card, pause menu) lives in its own script under `run/screens/` (see `docs/RUN_SCREEN_STRUCTURE.md`), and the animated code-drawn art is in `run/*_scene.gd`, `run/*_view.gd` (see `docs/*_ART_DESIGN.md`). Card effects (`combat/card_effect.gd`) are damage, block, draw, Expose, plus the Deserter's Hold (keep Block into the next turn), Block-scaled damage and thorns, the Thief's energy gain and damage that grows with the cards played earlier in the turn, and the Medium's Haunt (damage over time), HP costs, healing and damage from Haunt. Every launch opens a main menu (Continue when a valid save exists, New Run, Exit, and a persisted "Check for updates" toggle); New Run opens a character select screen with a Back button (name, HP, pitch and starting deck for each). Between stops it autosaves to `user://run_save.json` (`run/run_save.gd`, format version 4: crash-safe via `.bak`/`.tmp` fallback, v2 and v3 saves migrate on load; a Remembered deck card is saved as `id+`) and offers Continue on the main menu (a save is taken at the start of each stop, so quitting mid-stop and continuing replays that stop from its start: undoing a bad fight this way is intended); a Pause button (or Escape) opens a menu over an animated, code-drawn carriage backdrop (`run/pause_scene.gd`, with a detail per character) that freezes the fight and offers Continue, Save & Exit and New Run (with a confirmation); the end card summarises the run (outcome, stops cleared, HP, deck, gold).
- `tests/` - see `tests/README.md`: every `*_tests.gd` is discovered and run by `tests/run_tests.gd`; `tests/smoke_main.gd` loads and instantiates the main scene.
- `tests/ui_*_test.gd` - headless UI tests: the battle screen, whole runs driven through the real `run.tscn` buttons (`ui_flow_test.gd`), and each code-drawn view and scene. Each one is a step of `scripts/check.ps1` automatically.
- `scripts/check.ps1` - full validation: import, rules tests, smoke load and every UI test. Each step has a timeout (300 s, `CHECK_STEP_TIMEOUT_MS` to change) so a hang fails instead of blocking. CI runs it on every push (`.github/workflows/check.yml`, `docs/CI.md`).
- `installer/setup.iss`, `scripts/build_installer.ps1` - the Windows installer (`docs/INSTALLER.md`).

## Updates, settings and data migration

All of these live in `run/`. What each one trusts is the point of the split (details: `docs/UPDATE_CHECK.md`, `docs/UPDATE_SIGNING.md`).

- `update_check.gd` (`UpdateCheck`, static, no nodes or network) - decides which launches check for updates, validates the GitHub "latest release" reply, compares versions, builds the download URLs from a validated tag against a fixed host, and reads and writes the update manifest format. It trusts nothing in the reply except a tag that passes `is_valid_tag`. It also holds the download size caps (`MAX_INSTALLER_BYTES`, 400 MiB, kept at least 1.5x the latest installer by a test).
- `update_verifier.gd` (`UpdateVerifier`, static) - holds the maintainer's two public keys (`PUBLIC_KEY_PEMS`) and checks the manifest's RSA signature, its file name and version, and a file's SHA-256. It trusts only those embedded keys; with none embedded, verification always fails and in-game install stays off.
- `update_installer.gd` (`UpdateInstaller`, a node) - downloads the signature, the manifest and the installer into `user://update`, runs the installer only after the signature, the manifest's name and version and the installer's hash all check out (the hash is checked again on a private copy right before launch), and then closes the game. The copy and hash jobs run on one worker thread that does file work only. It trusts no downloaded byte, only the signed manifest.
- `update_notice.gd` (`UpdateNotice`, a node) - the update bar and the main menu's Update button. It makes the one GitHub request per launch (an asynchronous request, never awaited), feeds the reply to `UpdateCheck` and drives `UpdateInstaller`. Every failure is silent or falls back to opening the releases page.
- `settings.gd` (`Settings`) - player preferences in `user://settings.json` (the update-check switch, audio). The file is untrusted input: size-capped, type-checked, and any problem falls back to the defaults; unknown keys are kept and written back.
- `user_data_migration.gd` (`UserDataMigration`) - the one-time move of saves and settings from the pre-rename folder ("Card Battle Prototype") to "The Unforgotten". It copies and never overwrites a file that exists, and removes the old folder only after every copy succeeded. `installer/setup.iss` does the same move at install time; headless test runs never touch the real folders.
